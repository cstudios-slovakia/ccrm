# Update 1.13 (Codename: Nectarine) — New Features

This document tracks all new features, architectural changes, schema migrations, and improvements introduced in the 1.13 Nectarine update cycle.

### v1.13.0-Nectarine (2026-10-26)
- **Release Cycle 1.13 (Nectarine) Initialization (`src/utils/version.ts`, `1.13-nectarine-changelog.md`, `GEMINI.md`)**:
  - Initialized release branch `1.13-nectarine` branched from `1.12-mango` (v1.12.81-Mango).
  - Version bumped to `1.13.0-Nectarine` with codename `Nectarine`.

### v1.13.1-Nectarine (2026-10-26)
- **Settings → Orders: a status is still there after reload** (`public/sync.php`): adding or renaming one updated the screen and then came back as the built-in nine, with no warning. The server never stored `ORDER_STATUSES` and never returned it. It is now kept and sent back the same way offer statuses are, under `general_config`, which is the permission that screen already requires.
- **Settings → Tickets saves for someone who may edit settings but only view tickets** (`public/sync.php`): a status or the mailbox “from” name was dropped unless the role could edit tickets, even though the tab is opened by `general_config`. A `general_config` editor now reads and writes `TICKET_STATUSES` and `TICKET_SETTINGS`. Ticket fields that ride on a project, a lead or a task still require `tickets` = edit.
- **Settings → Users and Settings → Roles can be edited by an Admin only** (`src/components/SettingsView.tsx`, `public/sync.php`): a role with “Manage users” could rename a colleague or add a role, the screen kept it, and the reload put the old value back. The screens stay visible; the editors, including the role matrix, are locked for everyone else, with the read-only notice. A non-admin push that really does change another account or the registry is reported (`users`, `users:delete`, `roles`).
- **A save the server refuses is no longer silent** (`src/App.tsx`, `src/utils/syncDiff.ts`): taking a colleague’s login name or email, an out-of-scope lead or task, or a refused employee login used to look saved. Those tags now warn, and that collection is sent again. A tag the client does not recognise warns too.
- **Moving a salary to another month moves its expense with it** (`public/sync.php`): the linked expense kept the old issue date. The issue date is now updated with the period.
- **Tests**: `src/utils/syncDiff.test.ts`.
