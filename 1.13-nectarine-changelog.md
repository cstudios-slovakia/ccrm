# Update 1.13 (Codename: Nectarine) — New Features

This document tracks all new features, architectural changes, schema migrations, and improvements introduced in the 1.13 Nectarine update cycle.

### v1.13.0-Nectarine (2026-10-26)
- **Release Cycle 1.13 (Nectarine) Initialization (`src/utils/version.ts`, `1.13-nectarine-changelog.md`, `GEMINI.md`)**:
  - Initialized release branch `1.13-nectarine` branched from `1.12-mango` (v1.12.81-Mango).
  - Version bumped to `1.13.0-Nectarine` with codename `Nectarine`.

### v1.13.1-Nectarine (2026-10-26)
- **Settings → Orders: a status is still there after reload** (`public/sync.php`): adding or renaming one updated the screen and then came back as the built-in nine, with no warning. The server never stored `ORDER_STATUSES` and never returned it. It is now kept and sent back the same way offer statuses are, under `general_config`, which is the permission that screen already requires.
- **Settings → Tickets saves for someone who may edit settings but only view tickets** (`public/sync.php`): a status or the mailbox “from” name was dropped unless the role could edit tickets, even though the tab is opened by `general_config`. A `general_config` editor now reads and writes `TICKET_STATUSES` and `TICKET_SETTINGS`. Ticket fields that ride on a project, a lead or a task still require `tickets` = edit.
- **Settings → Users and Settings → Roles can be edited by an Admin only** (`src/components/SettingsView.tsx`, `public/sync.php`): a role with “Manage users” could rename a colleague or add a role, the screen kept it, and the reload put the old value back. The screens stay visible; the editors, including the role matrix, are locked for everyone else, with the read-only notice. A non-admin push that really does change another account or the registry is reported (`users`, `users:delete`, `roles`).
- **A save the server refuses is no longer silent** (`src/App.tsx`, `src/utils/syncDiff.ts`): taking a colleague’s login name or email, an out-of-scope lead or task, or a refused employee login used to look saved. Those tags now warn, and that collection is sent again. A tag the client does not recognise warns too.
- **Moving a salary to another month moves its expense with it** (`public/sync.php`): the linked expense kept the old issue date. The issue date is now updated with the period.
- **Tests**: `src/utils/syncDiff.test.ts`.

  - **No emoji** in `settings.tab.*`, group headings and settings headings (lucide icons instead); new strings in en, sk and hu (`translations.settingsNav.ts`, 278 keys).
  - New user preferences `settingsLayout` (`tiles` | `sidebar`) and `settingsRecents`, stored with the other per-user preferences.
- **No always-visible scrollbars in Settings (`ScrollFade`, `index.css`)**: wide tables, the section dropdown, the sidebar navigation, search results and the recents row hide the bar and fade the content out on each edge that has more behind it (driven by scroll position, so a list that fits shows no fade). Tile hover lift, the section flash, the results fade-in and the dropdown entrance respect `prefers-reduced-motion`.
- **Phone fixes found on the way**: the add-stage / add-source / add-category / add-division forms and the project-type cards wrap instead of widening the page; company mailboxes tolerate an answer without its lists instead of blanking the whole Email category. The add-stage / source / category / division buttons are disabled while their field is empty (they did nothing then; the QA crawler reported the division one as inert now that the Company page shows it).

### v1.13.3-Nectarine (2026-10-27)
- **Settings: every section is a real tab (`settings/SectionList.tsx`, `CategoryPage.tsx`, `SidebarLayout.tsx`, `SettingsView.tsx`)**: the tab strip used to scroll a long page of stacked cards; now only the open section is rendered. `#settings/<category>` opens the first tab, `#settings/<category>/<section>` that tab; arrow keys, Home and End move between tabs (`role="tablist"`), the sidebar sub-links and the phone dropdown open the same tabs, and a tab starts the page from the top. Sections that load data on open (system errors, API key, AI, custom records) now load when *their* tab opens.
- **No Save buttons in Settings: every setting saves itself** (`settings/useAutosave.ts`, `SectionCard.tsx`): Company (profile, brand name, billing details, bank, invoice defaults and VAT), outgoing e-mail, AI and vector database, Zernio key and existing custom record types write a moment after the last keystroke; each block's header shows *Saving… / Saved*. The phone's floating *Unsaved changes* bar and *Save profile* on a user are gone. The company forms patch only their own fields into the stored record, and a save echoing back no longer overwrites what is being typed. A new record type, a test e-mail, a connection test and resets keep their buttons — they are actions, not settings.
- **One block, one header (`SectionCard`)**: every block in Settings now has the same header — title, one-line description, action on the right, hairline — including the ones that were hand-built or embedded (divisions, project types, project and order statuses, ticket settings, price levels, payment and shipping methods, finance, licence, audit log, company mailboxes, tasks, lead assignment, modules, Zernio, system). Project types was a bare heading over the cards; it is a block like the statuses below it. `settingsRedesign.spec.ts` opens every section and fails on a block with another header.
- **Users and roles: creating is opt-in**: the *new user account* form is no longer a loose panel under the list — *Create a new user account* in the users block opens it inside that block (Cancel closes it); the same for *Create custom role*.
- **Modules & records rebuilt**: *Visible modules* is one search/filter block plus one block per category; *Record types* is a list block with a *New record type* action, and the editor is three blocks (name, icon & colour / fields / folders) instead of one long form. Editing an existing type saves itself; the form no longer reloads from storage while it is being typed in.
- **Language and country dropdowns show names only** (`PersonalSettingsView`, `Header`, `SettingsView`, `OrderDetailView`, `ClientsView`, `InstallerWizard`): Windows draws flag emoji as letters, so the lists read "SK Slovenčina / GB English / HU Magyar" and "Slovensko (SK)". They are now "Slovenčina / English / Magyar" and "Slovensko".
- **Settings labels use one colour** (`type-overline text-slate-500` instead of 400/500/600 depending on the card).
- **Tests**: `settingsRedesign.spec.ts` (tabs render one section, arrow keys, one header for every block, no Save buttons, add forms closed until asked, flag-free language list, autosave chip on a phone); `financeSettings`, `projectStatuses`, `companyMailboxes` and `navigation` specs now name the section they open.

### v1.13.4-Nectarine (2026-10-27)
- **Moved from 1.12-mango**: phase 1 was first committed on `1.12-mango` as v1.12.84 by mistake and was re-applied here on top of the 1.13 settings registry.
- **New module: Time tracking, phase 1 — core, holidays and cost** (`src/components/timeTracking/*`, `src/hooks/useTimeTracking.tsx`, `src/utils/{timeTracking,timeCost,holidays,timeLinks,timeTrackingApi}.ts`, `public/api/{time_entries,time_entries_lib,time_cost,holidays,holidays_lib}.php`, `public/api/schema.php`): a native, Toggl-style tracker. Route `time-tracking` (teal sidebar item, Start menu, Visible modules). Tabs **List** (week stat strip, day cards, bulk delete with Undo) and **Day** (14-day strip, hours-only "Add row" that accepts `1.5`, `1:30`, `90m`, rows grouped by person); the **timer bar** (title with open-task autocomplete, project, billable, Timer/Manual); the global **header pill** and the `▶ 1:12 · ` tab-title prefix; the right-hand **entry drawer**; the shared **project picker** (search, grouped by client, recent first, show finished, inline create). Calendar, Timesheet, Team, Reports, the Chrome extension, task/project entry points and tickets follow in later phases.
  - **One running timer per user, enforced by the database** (`UNIQUE running_guard`). Starting a timer stops the old one in one transaction and shows an Undo toast; a start that loses a race answers 409 with the entry that already runs. Elapsed time is `now − start`, never a tick count.
  - **A task-linked entry has no title of its own.** `time_entries.description` is the title only for entries with no task and no ticket; the API joins `tasks.title` / `tickets.title` live and returns `title` + `titleSource`. Editing the title of a linked entry saves the **task** through the normal app save path (conflict handling, audit, permissions); the field says "Renames the task" and is read-only when the user cannot edit that task. Unlinking prefills the entry's own title with the task's current title; linking an entry that has different text of its own asks first. `title_snapshot` is only the greyed fallback after the task or ticket was deleted.
  - **Cost rate by employment status** (`timeCost.ts`, ported to `time_cost.php`; both run `scripts/fixtures/time-cost-cases.json`): employee monthly / daily / hourly with the employer multiplier, contractor hourly / daily / monthly without it, nothing for a ledger line or a user with no employee. A monthly salary is divided by **that month's real working days in the person's country**, so Erik's €3,200 is €24.58/h in June 2026 (22 days) and €27.04/h in May (20 days), €25.75/h in October under the Hungarian calendar (21 days). The rate is frozen on the entry (`cost_rate`, `cost_rate_source`, `cost_rate_basis_days`, `cost`) when it is stopped or saved; Settings → Time tracking → *Re-price a period* (admin, hold to confirm) recomputes a month and fills entries that had no rate.
  - **Working days and public holidays for Slovakia and Hungary** (`holidays.ts`, `holidays_lib.php`, `holidays.php`, table `public_holidays`): fetched server-side from Nager.Date (5 s timeout, https only, the egress guard of `auth.php`), cached, refreshed monthly by `cron.php`; never on the sync probe path or in a migration. Offline, the statutory days are computed from their rules (`holidays.ts`, same rules in PHP) and Settings shows an amber "built-in list" note. Names come from an en/sk/hu map keyed by rule, so every language reads natively. **Which days are holidays depends on the person's work calendar** (`Employee.workCountry`, else the company's country), never on the UI language. Per-country, per-year **overrides** (extra day off / extra working day) cover Hungary's yearly decree days, for which no free machine-readable source exists. Holidays show in the Day strip, the List day-card header ("State holiday") and lower the weekly target; they never block logging.
  - **Cost is enforced server-side.** An entry's cost fields reach its owner always and anybody else only with `time_tracking_costs`; `billableRate` always needs it; without `time_tracking_team` the owner filter is forced to the caller. A user with no employee shows "no rate — no employee linked".
  - **RBAC**: new section `time_tracking` — `time_tracking` (access; existing roles keep it at *edit*, new roles start at *nothing*), `time_tracking_team`, `time_tracking_costs`, `time_tracking_salary_report` (toggles). Mirrored in `permissions.php` (test P1), labels in en/sk/hu, route `time-tracking` mapped in `permissionKeyForRoute`.
  - **Employees**: new optional **Work calendar** (Company default / Slovakia / Hungary) on the employee form → `employees.work_country`, synced with the pay group (`sync.php`, `read_scope.php`).
  - **Settings → Projects & tasks → Time tracking** (registry section `projects/time`; old `#settings/time-tracking` redirects): hours basis, hours per day, employer multiplier with a live example, holidays list and overrides, rules (require project / task, billable default, auto-stop, long-entry warning, idle reminder, lock window, rounding), re-price.
  - **Schema**: `time_entries`, `public_holidays`, `employees.work_country` (all in `schema.php`, fingerprinted). `ticket_id`, `title_snapshot`, `legacy_note` are in place for phase 2.
  - **Tests**: `timeCost.test.ts`, `holidays.test.ts`, `timeTracking.test.ts`, `timeLinks.test.ts`, two RBAC cases; `npm run test:time-cost` (PHP against the same fixtures); `npm run test:time-tracking` (61+ checks against the real PHP and a scratch database: cost per employment status, cost stripping, ownership, one-timer rule, the title rule, validation, soft delete, settings, holidays, re-price); `tests/e2e/timeTracking.spec.ts` with a stateful mock of the new endpoints in the QA fixture; Time tracking added to the crawler, dark-mode and view-size module lists.
  - **QA**: the browser QA audit (`npm run test:qa`) was **not run** for this build at the owner's request (the machine had no free RAM for it); `tests/e2e/timeTracking.spec.ts` is written but has never executed. Unit tests, the PHP parity test, the server probe (65 checks) and `tsc` were run.
