# Part B. Decisions (final)

1. **Live provider: Soniox** (`stt-rt-v6`), user's choice of 2026-11-06. It is the only provider found
   that documents *live* speaker diarization for both Slovak and Hungarian, and it costs $0.12/h with
   diarization included. OpenAI's only voice-diarization model (`gpt-4o-transcribe-diarize`) works on
   files only and shuts down on 2027-02-26.
2. **OpenAI live stays as the fallback.** Without a Soniox key the Focus helper behaves as in
   v1.13.64: no speakers, but the document still forms. The server decides the provider; the browser
   follows `provider`.
3. **The Focus helper still requires an OpenAI key** (the document and Catch me up use the configured
   cheap text model, `ccrm_ai_model()`). The switch's availability rule is unchanged.
4. **The master Soniox key never reaches the browser.** The browser gets a temporary key
   (`snx_temp_…`, 60 s to connect, session cap 5 h) and passes it in the WebSocket protocols list.
   The `api_key` field in the start message is deprecated and refused from 2027-01-15, so never use it.
5. **Speaker ids are app-level `P1`, `P2`, …**, assigned in order of first appearance. A provider label
   is mapped to a `P` id per stream. A new stream (reconnect, rotation) cannot know the old voices,
   so its speakers get new numbers. This is accepted: it is rare, and the user can rename chips.
6. **Pause keeps the Soniox stream open** (finalize, then keepalive) so speaker numbers survive a
   pause. Stop ends the stream.
7. **Endpoint detection off.** Soniox documents that endpoint detection lowers diarization accuracy.
   Turns are built from speaker changes and pauses in the token timestamps instead.
8. **The document is append-mostly.** Finished sections are frozen and never rewritten; only the last
   (open) section is rewritten on each update. This keeps the reader's place stable and bounds the
   cost of each call. After Stop, one final call closes the open section.
9. **Speaker attribution in the markdown is a token `[[P1]]`**, not a name. The panel renders it as a
   coloured chip with the current display name, so renaming a speaker needs no new LLM call.
10. **Nothing new is stored.** The document lives in memory like the live transcript. The official
    transcript after Stop is unchanged (`gpt-transcribe`); see D1 for the later option.
11. Cadence: about every 12–30 s (C3.3). At `gpt-6-luna` prices that's about $0.08 per meeting hour.

## C2. Soniox transport (phase 2)

Docs: <https://docs.soniox.com/stt/api-reference/websocket-api>,
<https://docs.soniox.com/authentication/websocket-authentication>,
<https://docs.soniox.com/stt/rt/manual-finalization>, the connection-keepalive page. Confirm the

### C2.1 Temporary key (server)

`POST https://api.soniox.com/v1/auth/temporary-api-key`, `Authorization: Bearer <sonioxApiKey>`, JSON:

```json
{ "usage_type": "transcribe_websocket", "expires_in_seconds": 60,
  "client_reference_id": "ccrm-user-<user id>", "max_session_duration_seconds": 18000 }
```

→ 201 `{ "api_key": "snx_temp_…", "expires_at": "…" }`. Reuse `ccrm_live_openai_post`-style curl
(rename or add a generic helper; keep the OpenAI one working). On a non-2xx answer return the HTTP
code and Soniox's message, like the OpenAI branch does. Decrypt the key through the existing
`ccrm_decrypt_config_secrets` (phase 1 registers `sonioxApiKey`). Response to the browser:

```json
{ "success": true, "provider": "soniox", "api_key": "snx_temp_…", "model": "stt-rt-v6",
  "ws_url": "wss://stt-rt.soniox.com/transcribe-websocket", "expires_at": "…" }
```

Model and URL are pinned on the server and never read from the request.

### C2.2 Session (browser)

- `new WebSocket(ws_url, ["soniox-api-key", api_key])`. On open, send the start message:
  `{ model, audio_format: "pcm_s16le", sample_rate: 16000, num_channels: 1, language_hints: <the hook's languages>, enable_speaker_diarization: true, enable_endpoint_detection: false }`.
  **No `api_key` field.**
- Then stream binary PCM frames (~100 ms each).
- **Pause** (`running` false while `enabled` and the recording still exists): stop sending audio, send
  `{"type":"finalize"}`, then a keepalive (`{"type":"keepalive"}`, confirm the format) every 20 s.
  **Resume:** send audio again on the same socket.
  The current effect closes the session whenever `running` turns false. For Soniox, split it so the
  socket lives for the whole recording and only the audio flow follows `running`.
- **Stop** (`recordingState` "stopped"/"none", or the stream changes): finalize, send an empty **text**
  frame, wait up to 3 s for `finished: true`, close.
- **Errors:** a response with `error_code` is a server error; codes for an expired or invalid key
  during a reconnect go through the backoff. Reuse `liveReconnect.ts`
  (`nextReconnectDelay`, `failuresAfterDrop`). Every reconnect mints a new temporary key. The first
  connection failing is an immediate error with Retry (same rule as today).
- **Rotation:** a stream carries at most 300 min of audio. At 290 min of audio, open a new stream and
  then close the old one, as `rotate` does today. The new stream's speakers get new numbers (B5).
- **Usage:** report streamed audio seconds with `reportLiveTranscriptionSeconds(sec, "stt-rt-v6")` in
  60 s checkpoints, and only while audio is being sent (not during pause).
- The OpenAI path (`liveCommitVad`, WebRTC, rotation) is untouched.

### C2.3 `sonioxTokens.ts` (pure)

```ts
export interface SonioxToken { text: string; start_ms?: number; end_ms?: number; is_final?: boolean; speaker?: string }
export interface SonioxState { /* final turns so far, current non-final tokens, speaker map, stream number */ }
export const createSonioxState: () => SonioxState;
/** A new stream (reconnect/rotation): bump the stream number so its labels map to new P ids. */
export const nextStream: (s: SonioxState) => SonioxState;
export const applySonioxResponse: (s: SonioxState, res: { tokens?: SonioxToken[] }, elapsedOffsetSec: number) => SonioxState;
export const sonioxSegments: (s: SonioxState) => LiveSegment[];
```

- **Final tokens arrive once; non-final tokens are re-sent in every response and replace the previous
  non-final set.** Confirm this against the docs; it is the documented accumulation model.
- Drop the control tokens `<fin>` and `<end>`.
- A **turn** is consecutive final tokens with the same speaker. A new turn starts when the speaker
  changes, or after a gap of more than 1.5 s between `end_ms` and the next `start_ms`.
- Non-final tokens form the trailing in-progress turn(s), with `final: false`. They are split by
  speaker too.
- Segment ids are stable (`s<stream>-t<n>`), so React keys and the document's pending tracking hold.
  The in-progress turn keeps its id once it becomes final.
- `startSec` is the elapsed recording time. A stream's `start_ms` counts audio sent on that stream,
  so pass the elapsed time at stream start as `elapsedOffsetSec`. Pauses don't advance `start_ms`
  (no audio), and they don't advance the recording clock either, so the two stay aligned.
- Speaker map: `(stream, sonioxLabel) → "P<n>"`, where n increments on first appearance across the
  whole recording.
- Tests: final/non-final replacement, speaker split, gap split, control tokens dropped, id stability
  when non-final becomes final, numbering across `nextStream`, tokens without speaker.

### C2.4 Audio capture

- Clone the recorder's track (as today; never touch the MediaRecorder or call `getUserMedia`).
- Convert to 16 kHz mono signed 16-bit little-endian. Preferred: an **AudioWorklet loaded from a
  same-origin file**. The CSP `script-src` has no `blob:`, so a blob-URL worklet fails in production.
  With Vite, `import url from "./pcmCaptureWorklet.js?url"` emits a same-origin asset. A plain
  `.js` worklet in `src/` is acceptable. Run the AudioContext at the device rate and resample in the
  worklet (linear interpolation is enough for speech), because Firefox refuses to connect a
  MediaStream source to a context running at a different sample rate.
- Fallback when `audioWorklet` is missing: `ScriptProcessorNode` with the same resampler.
- Put the resampler in a pure `.ts` (e.g. `src/utils/pcmResample.ts`) with a unit test, and have the
  worklet carry its own copy (worklets can't import app modules); comment that the two must match.

## C3. Live document (phase 3)

### C3.1 `public/api/live_meeting_document.php`

Same skeleton as `live_transcription_session.php`: POST only, `ccrm_require_auth`,
`ccrm_require_perm($pdo, $user, 'meetings', 'edit')` **before** reading the config, OpenAI key from
`INTEGRATIONS_CONFIG` (decrypted), rate limit `live_meeting_document` 360/hour/user → 429.

Request:

```json
{
  "language": "sk",
  "outline": ["Úvod a cieľ stretnutia", "Rozpočet projektu Nova"],
  "open_section": "## Termíny\n- [[P1]] Navrhuje …",
  "turns": [ { "speaker": "P2", "at": "12:41", "text": "…" }, { "at": "12:50", "text": "…" } ],
  "final": false
}
```

Caps (reject 400 or trim): outline ≤ 40 entries × 120 chars, `open_section` ≤ 8000 chars, turns ≤ 80,
total turn text ≤ 12000 chars, `speaker` must match `^P\d{1,2}$` or is dropped.

Call `ccrm_ai_model($integrationsConfig)` via chat completions with
`response_format: {"type":"json_object"}`, plus `temperature` 0.3 when
`ccrm_ai_model_supports_temperature`. If the model rejects `response_format` (400), retry once
without it and parse the first `{…}` block. Timeout 30 s.
`ccrm_ai_capture_usage($pdo, 'meeting_live_document', $decoded, $model)`.

Response: `{ "success": true, "sections": [ { "markdown": "## …", "closed": true|false } ] }`.

Server-side validation of the model's answer:

- 1–6 sections, each ≤ 8000 chars, each starting with `## ` (prepend a heading from the first line if
  missing).
- When `final` is true, every section is closed.
- Otherwise every section except the last is closed. Force it if the model got it wrong.
- Strip raw HTML tags.
- Drop `[[…]]` tokens that don't match the grammar (C1.4).

### C3.2 The prompt (write it in the PHP file; the rules below are the content)

- The model maintains **live meeting minutes** in Markdown, written in the language the participants
  speak (if unclear or mixed, in `language`).
- **Input:** the headings of the sections already written (context only; never repeat or rewrite
  them), the current open section (may be empty), and the new transcript turns.
- **Output:** JSON `{"sections":[{"markdown":"…","closed":bool}]}`. The first section is the open
  section rewritten so it absorbs the new turns. Further sections start when the topic changes. Close
  a section when its topic is finished. Keep the open section under ~2500 characters; close it and
  start a new one if it grows past that.
- **Structure:** each section starts with `## Heading` (short, specific: "Rozpočet projektu Nova", not
  "Diskusia"). Use `###` for a sub-topic inside a long section. Use bullet lists for points,
  options, enumerations and steps. Use **bold** for decisions, numbers, amounts, dates, deadlines,
  owners and names of projects/companies. Use *italics* for tentative or unclear points ("asi",
  "možno") and asides. Use a `> ` quote only for a short, important verbatim sentence. A decision line
  starts with a bold localised label (**Rozhodnutie:** / **Decision:** / **Döntés:**), and an action
  item likewise (**Úloha:** / **Action:** / **Feladat:**), with the owner when known.
- **Speakers:** when turns carry `speaker`, start a paragraph or bullet with the token, e.g.
  `- [[P2]] Navrhuje posunúť termín na **15. decembra**.` Repeat the token only when the speaker
  changes or attribution matters. Never invent a speaker; turns without `speaker` get no token. Never
  write "Participant 2" as text; use the token.
- **Fidelity:** minutes, not a verbatim transcript. Drop fillers and false starts, merge repetition,
  fix an obvious recognition error only when certain. Never add facts, conclusions or numbers that
  aren't in the turns. Never drop content that is already in the open section; you may restructure it.
- **`final: true`:** the meeting has ended. Finish the open section and close everything; don't write
  a summary section.

### C3.3 `src/utils/liveDocument.ts` (pure)

State: `sections`, `consumedIds: Set<string>`, `lastRequestAt`, `inFlight`, `failures`,
`nextRetryAt`, `finalDone`.

- **Pending** = segments with `final && !failed && text.trim()` whose id isn't consumed, in array
  order. Non-final segments are never sent.
- **Update now?** (no request in flight, and `now >= nextRetryAt`):
  - recording: pending words ≥ 40 and ≥ 12 s since the last request, or any pending and ≥ 30 s;
  - paused: any pending (once the pause starts);
  - stopped: any pending, or `!finalDone` with an open section, sent as `final: true`. After the
    final call, stop.
  - Never less than 8 s between requests, except the final one after Stop.
- **Build request:** outline = headings of the closed sections (first `## ` line, stripped); open
  section = the last section if not closed, else ""; turns = pending as `{speaker?, at: formatClock(startSec), text}`,
  at most 80 turns / 12000 chars (send the oldest; the rest stays pending).
- **Apply response:** replace the open section (if any) with the returned sections; reuse the open
  section's id for the first returned one so React keeps the node. Mark the sent ids consumed. Reset
  failures.
- **Failure:** the sent ids stay pending. Retry after 10 s, then 30 s, then every 60 s. `status`
  becomes `"error"` from the 3rd consecutive failure, and the next success clears it.
- `splitSpeakerTokens` per C1.4.
- Tests for every bullet above.

### C3.4 `src/hooks/useLiveDocument.ts`

A thin driver: a 2 s interval tick (only while enabled and not "none") calls the pure "update now?"
check, posts to `/api/live_meeting_document.php` (`credentials: "same-origin"`), and applies the
result. Ignore a response that arrives after `clear()` or a new recording (use a generation counter).
Clean up the interval on unmount.

# Part D. Later options (not scheduled)

## D1. Soniox for the official transcript after Stop

Today, after Stop the whole recording goes to OpenAI `gpt-transcribe` ($0.27/h, plain text, no
speakers; `public/api/transcribe_meeting.php`). Soniox async transcription costs $0.10/h with speaker
diarization included, and Soniox documents that async diarization is **more accurate** than real-time.
Switching would give the official transcript real `[mm:ss] Participant N: text` lines, the shape the
demo data already uses, and cut the cost by about 60 %. To weigh before doing it:

- An async job is upload → poll → fetch, so `transcribe_meeting.php` needs a job flow or a longer
  request.
- The speaker numbers from the async pass won't match the live chips; the renames would need mapping
  (e.g. by overlap in time).
- Keep `gpt-transcribe` as the fallback when no Soniox key is set, as in Part B2.
- Check Slovak/Hungarian accuracy against `gpt-transcribe` on a real recording first.
