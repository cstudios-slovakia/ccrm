- **Exchange Online (Microsoft 365) mailboxes: sign in with Microsoft instead of a password** (`api/graph_client.php`, `graph_mail.php`, `graph_filing.php`, `graph_oauth.php`, `mail_broker.php`, `mail_filing.php`, `MicrosoftMailConnect.tsx`, `MicrosoftAppSettings.tsx`, `PersonalSettingsView.tsx`, `CompanyMailboxSettings.tsx`): Microsoft no longer accepts a password for IMAP or SMTP in Exchange Online, so such a mailbox could not be connected at all and its mail never reached a timeline. A mailbox of the new type *Microsoft 365 / Exchange Online* is connected with a **Sign in with Microsoft** button (Personal settings → E-mail, and per company mailbox in Settings → E-mail) and read and sent from through Microsoft Graph: inbox, message detail, attachments, read flag, delete and sending work as they do for IMAP, and the background job files incoming and sent mail onto timelines incrementally, each message once. When a sign-in expires or the consent is revoked, the mail screen, Personal settings and the company mailbox row say "sign in again", and the other mailboxes keep being read. An admin enters the Microsoft app registration once under Settings → E-mail → Company mailboxes → Microsoft 365 sign-in, which also shows the redirect URI to copy. Setup guide: `docs/MICROSOFT-365-MAIL.md`. IMAP mailboxes are unchanged.
- **Database** (`api/schema.php`, `entities_overview.md`): `mail_sync_state.delta_link` (the Graph delta link of a Microsoft 365 mailbox); the filing job adds it itself where the migration has not run yet.
- **Company mailboxes: the server of an IMAP mailbox can be changed again** (`api/company_mailboxes.php`): changing the host, port or login always answered "Please re-enter the password", even with the password typed in, because the check also looked for a password field this form never sends.
