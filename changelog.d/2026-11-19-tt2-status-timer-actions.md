- **Time tracking: task status starts, pauses or stops your own timer** (`src/utils/taskStatusTimer.ts`, `public/api/time_status_rule.php`, `src/components/timeTracking/TaskStatusTimerBridge.tsx`, `src/utils/taskStatusTimerHook.ts`, `public/api/time_entries.php`; tt2 phase 8b): when you change a task's status in the browser, the timer action mapped to the new status runs on your own timer on that task (a start only for a single-task change on a task you are assigned to or that has nobody assigned; pause and stop also on bulk edits). Colleagues' timers are never touched, and changes arriving by sync never fire. A toast confirms it ("Timer started / paused / stopped for “Task”"), with Undo for a start and a pause. The rule exists in TypeScript and PHP with shared fixtures (`npm run test:task-status-timer`). `POST pause` and `POST stop` accept `reason: 'status'` (`pause_reason` / `end_reason` 'status').
