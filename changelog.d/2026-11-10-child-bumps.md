- **A changed child row moves its record's `updated_at`** (`public/sync.php`, `public/api/sync_child_bumps.php`, `public/api/mcp.php`, `public/api/mcp_ext_writes.php`, `entities_overview.md`): "did anything about project X / invoice Y / meeting Z change today?" is now answered by `updated_at`. `sync.php` snapshots the set before its delete + insert, re-reads it after, and bumps the parent only when the stored content really differs, so an unchanged re-save leaves `updated_at` alone and never raises a false sync conflict. Covered: project managers and Gantt rows (`projects`), invoice line items (`invoices_offers`), meeting action items (`meeting_notes`), movement lines (`warehouse_movements`). The MCP `create_milestone` bumps the project too. Timeline entries and payments do not move it. Other open clients see one extra conflict check on a bumped record (the trade-off already accepted for task assignees and tags).
- **MCP `adjust_stock` stamps the movement with local time** (`public/api/mcp_ext_writes.php`): `warehouse_movements.issued_at` was MySQL `NOW()` (UTC on a server) while the app writes local wall time.
