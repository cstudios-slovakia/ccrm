- **Bug category from MCP, the integration API and workflows** (`mcp_ext_writes.php`, `mcp_lists_crm.php`, `integration_tasks.php`, `workflows_engine.php`, `AutomationView.tsx`): the MCP tools `create_task` and `update_task` take an optional `category` ("bug" marks the task as a Bug, an empty value clears it on update, leaving it out changes nothing; an invalid value is refused with a clear error), and `get_task` / `list_tasks` return it. The integration endpoint (`PUT /tasks/external/{id}`) accepts and returns `category` the same way (invalid is a 422 on `category`; documented in `docs/WAAI-INTEGRATION.md`). The workflow action "Create task" has a Category field ("No category" / "Bug"); existing workflows keep creating tasks without one. Tasks created this way count in the dashboard's bug time. A database that has not migrated the column yet keeps working: the statements leave `category` out until it exists.
- **Tests**: `taskCategory.test.ts` and `taskCategoryWrites.test.ts` (the shared category rule, the strict check, the statement variants with and without the column, and the MCP, integration and workflow call sites); the PHP cases were run in docker.
