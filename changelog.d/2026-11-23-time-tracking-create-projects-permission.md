- **New role permission "Create projects from time tracking"** (`time_tracking_create_projects`; `src/utils/permissions.ts`, `public/api/permissions.php`, `public/api/read_scope.php`, `public/api/time_projects.php`, `App.tsx`, `createPickerProject.ts`): Settings → Users & roles → Time tracking now has a toggle that decides whether a role may create a project from the time-tracking project picker without the Projects module. It needs Time tracking = edit and is on by default, for existing roles too, so nothing changes until an admin turns it off. Picking any active project is not affected. The server refuses `api/time_projects.php` without it (403 `forbidden`). Roles with Projects = edit keep creating projects as before. Settings → Time tracking → "Who sees what" shows which roles have it.
- **Tests**: `permissions.test.ts` (section keys, legacy default on); RBAC probe TP1–TP3 (slim picker list carries ids/names/client/status only; create allowed by default; refused and nothing written with the toggle off).
