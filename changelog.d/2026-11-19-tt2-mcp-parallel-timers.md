- **MCP: timer tools know about parallel timers**: `get_running_timer` lists every running timer in `timers` (keeping `running` for old clients); `start_timer` takes `mode` (`switch` stops every running timer, `parallel` keeps them, behind the company setting and the `time_tracking_parallel` permission) and returns `stopped_ids`; `stop_timer` takes `entry_id` or `all` and refuses to guess when several run. Every timer change takes the per-user lock.
- **MCP: starting what already runs no longer splits it**: `start_timer` for the running target changes nothing and answers `already_running` with that entry, as the app does.
- **MCP: worked time in the per-person summary**: `get_time_tracking_summary` with `group_by=user` adds `worked_hours` and `leverage` next to project hours.
