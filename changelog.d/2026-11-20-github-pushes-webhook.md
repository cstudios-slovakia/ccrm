- **Projects: GitHub pushes arrive in the system** (`public/api/github_webhook.php`, `public/api/github_pushes.php`, `public/api/project_pushes.php`, `public/api/github_integration.php`, `public/api/schema.php`, `public/sync.php`, `src/components/settings/GithubIntegrationSettings.tsx`, `src/components/projects/ProjectGithubFields.tsx`): a project can be paired with a GitHub repository ("Repozitár") and, optionally, a server branch ("Vetva"; empty means the repository's default branch) in the project detail. GitHub delivers every push to a webhook of this system, which checks the signature and stores one record per push and paired project; the system counts pushes to the project's server branch, not pull requests, and keeps no GitHub token anywhere. Administrators set it up in Settings, Integrations, GitHub: the page shows the webhook address with a copy button, generates the secret key (shown exactly once, stored encrypted, never sent to the browser again; generating a new one asks for confirmation because the old one stops working) and lists the steps to take in GitHub. The pairing is saved with the project; a client that does not send it leaves the stored values alone, and a pasted `https://github.com/owner/name.git` is reduced to `owner/name`. A delivery with a wrong or missing signature is refused with a generic answer; a redelivery, and a replay of a signed delivery under a new delivery id, is stored once (a push is identified by its content); a push is dated by the moment this system received it, not by the commit's own date; the compare link is kept only when it is a GitHub compare or commit link; and tags and deleted branches are ignored. A project save from a browser tab that did not change the pairing never overwrites a pairing a colleague set meanwhile. When the stored secret key can no longer be decrypted, Settings says so and asks for a new one. Reading is `api/project_pushes.php` (pushes per project in a range of days, and one project's pushes); the timeline and the "Nasadenia na server" widget show them (below). New table `project_pushes` and two nullable columns on `projects` (`github_repo`, `github_branch`) with migration, sync column healing and `entities_overview.md`.
- **Projects: GitHub pushes on the timeline and in the dashboard** (`src/components/projects/ProjectPushTimelineItem.tsx`, `src/hooks/useProjectPushes.ts`, `src/utils/projectPushTimeline.ts`, `src/components/dashboard/performance/DeploymentsCard.tsx`, `src/components/dashboard/performance/useOverviewPushes.ts`, `src/utils/performance/deployments.ts`): every push of a project paired with a repository now appears in the project's timeline as a read-only item "Push na server" (branch, number of commits, who pushed, the first line of the last commit message, the time, and a "Zobraziť na GitHube" link that is shown only for a genuine GitHub compare or commit address); pushes are placed among the project's own events by time, cannot be edited or deleted and are not saved with the project, and when they cannot be loaded the timeline still shows its own events plus one quiet line. On the dashboard's overview tab the widget "Nasadenia na server" shows the pushes of the selected period (total, the latest one with its project, and the five projects with most pushes with the time of their last push, in amber when it is older than 14 days); it keeps "Projekty zatiaľ nie sú prepojené s GitHubom." while no project is paired, shows "Načítavam…" while loading and says "Údaje sa nepodarilo načítať." or "Projekty nie sú pre vás dostupné." when the data is missing or the user may not view projects. Open pages do not update live; reopening the tab or the period shows new pushes.
