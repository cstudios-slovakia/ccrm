- **Projects: GitHub pushes arrive in the system** (`public/api/github_webhook.php`, `public/api/github_pushes.php`, `public/api/project_pushes.php`, `public/api/github_integration.php`, `public/api/schema.php`, `public/sync.php`, `src/components/settings/GithubIntegrationSettings.tsx`, `src/components/projects/ProjectGithubFields.tsx`): a project can be paired with a GitHub repository ("Repozitár") and, optionally, a server branch ("Vetva"; empty means the repository's default branch) in the project detail. GitHub delivers every push to a webhook of this system, which checks the signature and stores one record per push and paired project; the system counts pushes to the project's server branch, not pull requests, and keeps no GitHub token anywhere. Administrators set it up in Settings, Integrations, GitHub: the page shows the webhook address with a copy button, generates the secret key (shown exactly once, stored encrypted, never sent to the browser again; generating a new one asks for confirmation because the old one stops working) and lists the steps to take in GitHub. The pairing is saved with the project; a client that does not send it leaves the stored values alone, and a pasted `https://github.com/owner/name.git` is reduced to `owner/name`. A delivery with a wrong or missing signature is refused with a generic answer, a redelivery is stored once, and tags and deleted branches are ignored. Reading is `api/project_pushes.php` (pushes per project in a range of days, and one project's pushes); the timeline and the "Nasadenia na server" widget that show them come in the next package. New table `project_pushes` and two nullable columns on `projects` (`github_repo`, `github_branch`) with migration, sync column healing and `entities_overview.md`.
- **Tests**: `githubRepo.test.ts` (repository and branch normalisation). The webhook's pure functions, the signature check (a real HMAC of a sample body and GitHub's documented test vector), the SQL and the HTTP endpoints were run in PHP against MariaDB 11.4 in docker (ping, push, other events, tags, deletions, redelivery, unpaired repository, default-branch and case-insensitive matching, bad, missing and unconfigured secret, body over 5 MB, wrong content type, missing table, the read API for an administrator, a role without the projects module and no session, and project saves through `sync.php` with the pairing keys present, absent and invalid).
