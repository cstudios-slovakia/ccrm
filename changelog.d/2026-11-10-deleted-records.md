- **Deleted records leave a tombstone** (`public/api/schema.php`, `public/api/deleted_records.php`, `public/sync.php`, `entities_overview.md`): a new table `deleted_records` (entity, id, name, who, when) gets one row for every business record that `sync.php` really deletes: the generic delete and the project delete, for leads and clients, tasks, meetings, projects, invoices and offers, financial movements, employees, salaries, vacations and the stock records. Nothing is logged for a delete the mass-delete breaker refused, a delete that matched no row, or a child rewrite (timeline entries, action items, line items, Gantt rows, managers). The write is fail-soft and `sync.php` heals the table before its transaction, so a push never answers 500 over it. Deletions are recorded from this version on; earlier ones are not known. The table is read by the MCP tool `list_deleted_records`.
- **Tests**: `scripts/probe-persistence.mjs` (`changeVisibilityChecks`: named deletes of a lead, a client record, a meeting, an invoice, a movement and a project are logged with name, user and client flag; child rewrites and a repeated delete log nothing).
