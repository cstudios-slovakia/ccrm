- **Time tracking: the presence cycle in the provider** (`src/utils/timePresence.ts`, `useTimeTracking.tsx`): the provider now holds the server's presence state as a typed `TimePresence`, derives the phase locally (tracking, question at 50 min, "pausing…" at the deadline until the server confirms), the ring fill and the countdowns to the question, the pause and the end of the resume window, all on one clock corrected by the server time. `confirm()` answers "Still working"; a late answer re-reads the paused state, and an answer in one tab updates every tab. Groundwork for the cycle ring and the question dialog.
- **Tests**: `timePresence.test.ts` (each phase boundary, clock offset, presence checks off); the QA time-tracking mock models the cycle (anchor on start, resume and confirm; pause at the deadline) and lets a spec jump into it with `window.__ttPresence = { minutesIn }`.
